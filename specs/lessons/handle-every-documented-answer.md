# Decide what the page does with every answer an endpoint documents

- **Added:** 2026-11-02 · **Applies to:** spec | implement | review · **Issue:** TAS-147, TAS-201, TAS-217
- **Paths:** `frontend/src/**/*-api.ts`, `frontend/src/**/*-page.test.tsx`
- **Rule:** `pnpm test` fails when a documented non-2xx answer of a mutation (sent as `api.<METHOD>('<path>'`, or an `XMLHttpRequest` opened with `` `${apiBaseUrl}<path>` ``) has no page test, or its hook has no `response.status === N` (or `request.status === N`) branch and no entry with a reason in `UNBRANCHED` (`frontend/src/test/documented-answers.ts`, run by `frontend/vitest.documented-answers.ts`). It can't say what the branch does, so decide that on purpose. A `404` meaning the caller's household changed under the page invalidates `HOUSEHOLD_KEY` (as `useRemoveMember` does) instead of throwing into the "Check your connection" toast. A page that takes more than one branch on an answer needs a test for each: a `403` that asks the session again needs one where the session says signed out and one where it still says signed in (a refused CSRF token, or the check failing), and the second must still tell the person the change wasn't saved. A spec's API section that lists `| 404` says what the page does with it. The check sees only `backend/schema.yml`, so a status only the platform sends (Vercel's `413` on a request body over 4.5 MB) goes in the view's `@extend_schema` responses too, its description saying the platform sends it.
- **Why:** On PR #115 the invite link's make and cancel threw on the backend's `404` (the caller moved out of the household meanwhile), so the toast blamed the connection, the page kept the old household and every retry got `404` again. The spec listed the `404` but not what the page did with it. On PR #122 (TAS-151) Save on a `403` asked the session again and stopped there, so a person still signed in was told nothing; only the signed-out branch had a test. On PR #194 (TAS-183) the photo upload's `413` from Vercel wasn't in the schema, so nothing required its branch or page test.
