# Add ingredient lines and groups to the recipe form

Linear: TAS-116

## Summary

A household recipe can be added and edited (TAS-114, TAS-115), but not its ingredients. This lets someone writing a recipe give its ingredient lines, in optional groups, picked from the shared ingredient list by name or synonym, and add an ingredient the list doesn't have. An added ingredient awaits review: until staff check what it contains in the admin, recipes using it show no diet tags (their household is told why), and only households whose recipes use it are offered it. The catalogue load leaves added ingredients alone.

It ships in two parts, each its own PR to `main`:

- **Part 1 (this issue, TAS-116):** the model, the API that saves lines and groups and adds an ingredient, diet tags, the admin, the catalogue load, the seed and the "What's missing" line.
- **Part 2 (a sub-issue filed at approval):** the Ingredients section of the recipe form, built to the approved design.

Evidence: feature. Part 1: the admin's ingredient pages and the "What's missing" line on a recipe using an added ingredient. Part 2: a walkthrough of writing a recipe's ingredients in the form.
Design: needed. The Picnic boards (`docs/design/picnic/recipe-new*.dc.png`) draw no ingredients section, so the form's lines, groups, move and remove buttons and the add option have no design. Part 1 changes nothing the design draws.
Components: Combobox (changed: an "Add" option at the end of its list).

## Product behaviour

One claim per acceptance criterion, in the issue's order, with the part that delivers it:

1. The recipe form takes ingredient lines, above the groups and in named groups. (API: part 1; form: part 2)
2. Each line picks its ingredient from the shared list, found by name or synonym. (part 2)
3. An ingredient not on the list can be added by name; until reviewed, recipes using it show no diet tags. (API, tags and the note: part 1; the form's add option: part 2)
4. Staff can review and change an added ingredient in the admin. (part 1)
5. Loading the catalogue leaves added ingredients alone. (part 1)

What else holds, each proved by a test below:

- An added ingredient awaiting review is offered only to households whose recipes use it; once reviewed, to everyone.
- Adding a name the list already has, ignoring case and accents, or one of its synonyms, gives the existing ingredient.
- A private recipe using an ingredient awaiting review says so in "What's missing": "No diet tags until we've checked chipotle paste".
- A recipe using an ingredient awaiting review is left out by every diet filter.
- Saving a recipe's ingredients replaces all its lines and groups; leaving both out of an edit keeps them.
- Lines and groups move up and down with buttons, and a line can move into or out of a group.
- Amounts are typed in one field: 2, 2.5, ½, 1 1/2, 2-3 or nothing for "to taste".

## Technical design

### How it works today

- `Ingredient` (`backend/recipes/models.py:395`) is only ever made by `load_catalogue`, which deletes every ingredient the file doesn't list (`services.py:68`). Its names are lower case except proper nouns ("Cajun seasoning"); the recipe page capitalises the first letter (`recipe-ingredients.tsx:27`).
- `NewRecipeSerializer` and `RecipeChangesSerializer` (`serializers.py:305-338`) take no lines or groups, so a household recipe has none unless the seed made them (`add_described_recipes`, `services.py:106`).
- `GET /api/ingredients/` (`views.py:163`) has `authentication_classes = []` and lists every ingredient with its synonyms for the browse filters (`recipe-filter-panel.tsx`, `active-filters.tsx`).
- `diet_tags()` (`services.py:407`) and `RecipeQuerySet.suiting()` (`models.py:119`) both read `RULED_OUT_BY`; an ingredient with every `contains_*` flag off allows every diet.
- `IngredientAdmin` (`admin.py:59`) is a `CatalogueAdmin`: no add, change or delete, with the catalogue notice on its pages.
- The frontend's session change resets every query but the household's (`households/session-api.ts:27`), so `['ingredients']` is fetched again after signing in or out.

`IngredientQuerySet` gains:

```py
def called(self, name: str) -> Ingredient | None:
    """The ingredient with this name or synonym, ignoring case and accents."""
    synonyms = IngredientSynonym.objects.filter(name__unaccent__iexact=name)
    return self.filter(Q(name__unaccent__iexact=name) | Q(pk__in=synonyms.values('ingredient'))).first()

def offered_to(self, user: User | AnonymousUser) -> IngredientQuerySet:
    """Every ingredient but those awaiting review, which only households whose recipes use them are offered."""
    checked = ~Q(status=IngredientStatus.AWAITING_REVIEW)
    household_id = user.household_id if user.is_authenticated else None
    if household_id is None:
        return self.filter(checked)
    used = IngredientLine.objects.filter(recipe__household_id=household_id).values('ingredient')
    return self.filter(checked | Q(pk__in=used))

def unique_slug_for(self, name: str) -> str:
    # Cut short so a "-2" still fits the field's 100 characters.
    base = (slugify(name) or 'ingredient')[:90].strip('-')
    taken = set(self.filter(slug__startswith=base).values_list('slug', flat=True))
    return first_free_slug(base, taken)
```

#### Services (`backend/recipes/services.py`, edit)

```py
@dataclass(frozen=True)
class IngredientList:
    """A recipe's ingredient lines as the form sends them: the lines above every group, then each group with its
    own. A line is {amount, amount_max, unit, ingredient: Ingredient, note, optional, original_text}; a group is
    {name, lines}."""

    lines: list[Record]
    groups: list[Record]


def add_ingredient(name: str) -> tuple[Ingredient, bool]:
    """The ingredient with this name or synonym, ignoring case and accents, or a new one awaiting review under the
    name as given. True when it's new."""
```

- `add_ingredient` returns `(found, False)` when `Ingredient.objects.called(name)` finds one. Otherwise it creates `Ingredient(name=name, slug=Ingredient.objects.unique_slug_for(name), status=IngredientStatus.AWAITING_REVIEW)` inside `transaction.atomic()`. On `IntegrityError` (two people adding the same name at once) it looks the name up again and returns `(found, False)`, re-raising when there's still none. The name is stored as given (already trimmed and with its spaces collapsed); staff correct its case at review.
- `add_recipe(author, details, cuisines, courses, ingredients: IngredientList)`: after `courses.set`, calls `_set_ingredients(recipe, ingredients)`.
- `edit_recipe(recipe, details, cuisines, courses, ingredients: IngredientList | None)`: after `courses`, calls `_set_ingredients(recipe, ingredients)` unless it's `None`. The docstring says "None leaves the cuisines, courses or ingredients as they are."
- `_set_ingredients(recipe: Recipe, ingredients: IngredientList) -> None`: deletes the recipe's lines, then its groups; `bulk_create`s the groups with `position` from their order; then `bulk_create`s every line with `group` set (`None` above the groups) and `position` from its order within its own list, as `_lines` does for the catalogue. Four queries however many lines there are. The serializer has already checked each line (below), so the database constraints are only a backstop and no `full_clean` runs per line.
- `load_catalogue`: line 68 becomes `Ingredient.objects.filter(status=IngredientStatus.CATALOGUE).exclude(pk__in=[...]).delete()`, with the comment "Ingredients people added aren't the file's." A file ingredient whose slug matches an added row's takes that row over, as `_load_named` already does by slug: the row is made afresh, so its status goes back to `catalogue` and every line using it keeps pointing at it.
- `_plain_fields`: the set of fields the loader gives becomes `{'position', 'slug', 'status'}`, and its comment "Position comes from the order in the file, and ids, slugs and status are the loader's to give." A file giving `status` is refused with "has fields the catalogue does not know: status".
- `diet_tags(lines)`: lists `lines` once, then returns `[]` when any line's ingredient `awaiting_review`, before the existing rule, with the comment "An ingredient someone added says nothing of what it contains until staff review it." `diet_tag_conflicts` follows, as it starts from `diet_tags`.

    """The name of an ingredient someone adds from the recipe form."""

    name = serializers.CharField(
        max_length=100,
        error_messages={
            'blank': NO_INGREDIENT_NAME,
            'required': NO_INGREDIENT_NAME,

        },

    def validate_name(self, name: str) -> str:
        collapsed = ' '.join(name.split())
        if not any(character.isalpha() for character in collapsed):
            raise serializers.ValidationError('Give the ingredient a name with a letter in it.')
        return collapsed


class NewIngredientLineSerializer(serializers.Serializer):
    amount = serializers.DecimalField(
        max_digits=8, decimal_places=3, coerce_to_string=False, allow_null=True,
        min_value=Decimal('0.001'), error_messages={'min_value': 'Give an amount above 0, or leave it empty.'},
    )
    amount_max = serializers.DecimalField(max_digits=8, decimal_places=3, coerce_to_string=False, allow_null=True)
    unit = serializers.ChoiceField(choices=Unit.choices, allow_blank=True)
    ingredient = serializers.SlugRelatedField(slug_field='slug', queryset=Ingredient.objects.all())
    note = serializers.CharField(max_length=200, allow_blank=True)
    optional = serializers.BooleanField()
    original_text = serializers.CharField(max_length=300, allow_blank=True)

    def validate(self, line: dict[str, Any]) -> dict[str, Any]:
        # The model's range_rises constraint, checked here so a refusal names its line.
        if line['amount_max'] is not None and (line['amount'] is None or line['amount_max'] <= line['amount']):
            raise serializers.ValidationError({'amount_max': 'Give a range with its lower amount first, such as 2 up to 3.'})
        return line


class NewIngredientGroupSerializer(serializers.Serializer):

#### Amounts (`frontend/src/recipes/read-amount.ts`, new)

```ts
export type AmountReading =
  | { kind: 'amount'; amount: number | null; amountMax: number | null }
  | { kind: 'unreadable' }
  | { kind: 'zero' }
  | { kind: 'falling' };

// What someone typed in a line's Amount: "2", "2.5", "½", "1½", "1 1/2", "2-3", "2 to 3", or nothing for "to taste".
export const readAmount = (text: string): AmountReading;

// A line's amount as the form shows it: "2", "0.5", "2-3", or '' for none.
export const amountText = (amount: number | null, amountMax: number | null): string;
```

- A number is digits with an optional `.` and decimals; a fraction `a/b` with `b` above 0; a vulgar fraction (`¼ ½ ¾ ⅓ ⅔ ⅕ ⅖ ⅗ ⅘ ⅙ ⅚ ⅛ ⅜ ⅝ ⅞`) alone or after a whole number, with or without a space; or a whole number, a space and a fraction.
- A range is two numbers joined by `-`, `–`, `—` or `to`, with any spaces around it.
- Each number is rounded to 3 decimal places (the API's). Above 99999.999 is `unreadable`.
- Blank or spaces is `{ amount: null, amountMax: null }`. A range whose ends are equal reads as the single amount. A 0 anywhere is `zero`; a falling range is `falling`; anything else is `unreadable`.

#### The section (`frontend/src/recipes/recipe-form-ingredients.tsx`, new)

The draft is one flat list in the order the form shows it: the lines above every group first, then each group's heading followed by its lines.

```ts
export type LineDraft = {
  kind: 'line';
  key: string; // `line-${id}` for a saved line, crypto.randomUUID() for a new one
  ingredient: { slug: string; name: string };
  amount: string;
  unit: Unit | '';
  note: string;
  optional: boolean;
  originalText: string; // kept as loaded and sent back unchanged; '' for a new line
};
export type GroupDraft = { kind: 'group'; key: string; name: string };
export type IngredientEntry = LineDraft | GroupDraft;

export const ingredientEntriesOf = (recipe: Recipe): IngredientEntry[];
export const checkIngredients = (entries: IngredientEntry[]): Record<string, string>; // keyed by field id
export const ingredientFieldIds = (entries: IngredientEntry[]): string[]; // `${key}-amount` and `${key}-name`, in order
export const toIngredientPayload = (entries: IngredientEntry[]): Pick<NewRecipe, 'ingredient_lines' | 'ingredient_groups'>;
export const IngredientsSection = (props: {
  entries: IngredientEntry[];
  onChange: (entries: IngredientEntry[]) => void;
  errors: Record<string, string>;
  fieldRef: (id: string) => (element: HTMLElement | null) => void;
}) => …;
```

- `ingredientEntriesOf` lists `recipe.ingredient_lines`, then every group (including one with no lines) and its lines. `amount` is `amountText(line.amount, line.amount_max)`.
- `toIngredientPayload` splits the list at each group heading: lines before the first heading are `ingredient_lines`; each heading with the lines after it is a group. Every line sends `amount` and `amount_max` from `readAmount`, `unit`, `ingredient` (the slug), `note` trimmed, `optional` and `original_text`.
- `checkIngredients` gives `${key}-amount` "Enter an amount like 2, ½ or 2-3, or leave it empty." (unreadable), "Enter an amount above 0, or leave it empty." (zero) or "Put the smaller amount first, like 2-3." (falling), and `${key}-name` "Give the group a name, like For the sauce." for a blank group name.

What the section shows, top to bottom (the design decides the layout):

| Part | Content |
| --- | --- |
| Heading | `<h2 id="recipe-form-ingredients">Ingredients</h2>`, in a `Section` like Times |
| Intro | "Pick each ingredient from the list, or add one it doesn't have. Write amounts like 2, ½ or 2-3, or leave the amount empty for “to taste”." in muted text |

| The add field above the groups | The Combobox labelled "Add an ingredient", placeholder "Type an ingredient", `emptyText` "No ingredients match.", `chosen={[]}` |

`format-quantity.ts` exports `units: Unit[]` (the keys of `unitNames`, in its order) and `unitLabel = (unit: Unit) => unitNames[unit].one`, so the select and the page read one list.

Behaviour:

- **Picking.** Each Combobox offers every ingredient from `useIngredients()` matching its own search (`matchesIngredient`), whether or not the recipe already uses it, with synonyms as the hint, as `IngredientPicker` does. Picking appends a line with that ingredient at the end of the Combobox's own list (above the groups, or that group), clears the search and moves focus to the new line's Amount. Announces "Added onion."
- **Adding.** A Combobox gets `addOption` `{ label: `Add “${text}”` }` when the trimmed search has a letter (`/\p{L}/u`), is 100 characters or fewer and names no ingredient in the whole list: `namesIngredient(ingredient, text)` (new in `ingredient-match.ts`) is true when `matchRange` covers the whole of the name or a synonym. `onAdd` calls `useAddIngredient().mutateAsync(text.trim())`. While it's pending, a `role="status"` line under the Combobox reads "Adding “chipotle paste”…" and a second add is ignored. On `added`, it appends a line with the answer's ingredient as picking does, and the hook has put the ingredient in `['ingredients']`.
- **Moving a line.** Its Move up swaps it with the entry before it, and Move down with the entry after it, so a line next to a group heading crosses it: up, to the end of the list above; down, to the start of that group. Move up is `disabled` on the first entry and Move down on the last. Announces "Moved onion up.", "Moved onion down.", "Moved onion into For the sauce." or "Moved onion above the groups."
- **Moving a group.** It moves with its lines past the group before or after it. Move up is `disabled` on the first group and Move down on the last. The lines above the groups never move under a group this way. Announces "Moved group For the sauce up." or "…down."
- **Removing.** Remove on a line drops it, announces "Removed onion." and moves focus to its list's Combobox. Remove on a group drops only its heading, so its lines join the list above it; it announces "Removed group For the sauce. Its ingredients joined the list above." and moves focus to "Add a group".
- **Adding a group.** Appends a group with a blank name at the end, announces "Added a group." and moves focus to its Group name.
- **Focus after a move.** It stays on the button pressed, in the line's or group's new place. `IconButton` is `aria-disabled`, so the button keeps focus when the move makes it disabled. The section keeps `{ key, control }` of the last action in state and passes that control a ref callback that focuses it, as `household-page.tsx` does (lesson `confirm-dialog-takes-focus-back.md`).
- **Loading the list.** While `useIngredients()` has no data, the Comboboxes aren't shown; one `role="status"` line under the intro reads "Loading ingredients…" with a `Spinner`, and on error an `ErrorWithRetry` "Couldn't load the ingredients", "Check your connection, then try again.", retrying the query (keyed on `errorUpdatedAt`, as `ChipGroup` is). Lines already in the draft stay editable.

## Decisions

- Two PRs: part 1 the model, API, diet tags, admin, load and seed with the "What's missing" line; part 2 the form, because together they pass 600 lines and part 1 reviews on its own. Asked: ship as two PRs? → Two parts.
- An ingredient awaiting review is offered only to households whose recipes use it, and to everyone once reviewed, so unchecked names stay out of other people's pickers and the public filters. Asked: who is offered an added ingredient before review? → Households using it.
- An amount is one text field read by `readAmount` (2, 2.5, ½, 1 1/2, 2-3, 2 to 3), because recipes are written that way; the parser has a table test. Asked: how is an amount typed? → One field.
- Lines and groups reorder with Move up and Move down buttons, which work by keyboard and screen reader without a library. Asked: can lines and groups be reordered? → Move up and down buttons.
- A private recipe using an ingredient awaiting review says "No diet tags until we've checked chipotle paste" in "What's missing", so a household knows why its vegan recipe lost its sticker. Asked: say why there are no diet tags? → Say so in What's missing.
- No limit on adding ingredients for now; repeats reuse the existing one, ignoring case and accents. Asked: limit adding per account? → No cap for now.
- `Ingredient.status` is one field (catalogue, awaiting review, reviewed), not two booleans, so no impossible pair can be stored, and the load and the admin read the same field. (agent)
- A recipe with any line using an ingredient awaiting review, optional or not, has no diet tags and no diet tag conflicts, as the issue says "recipes using it", and an unchecked optional ingredient's conflict would be a guess. (agent)
- An added ingredient keeps the name as typed (trimmed, spaces collapsed), not lower-cased, because the catalogue keeps proper nouns' capitals ("Cajun seasoning") and the page capitalises the first letter anyway; staff fix the case at review. This corrects the spec brief, which said names are stored lower-cased. (agent)
- `POST /api/ingredients/` answers 200 with an existing ingredient and 201 with a new one, so the form treats both alike and adding a name twice can't make two. (agent)
- Sending either `ingredient_lines` or `ingredient_groups` replaces every line and group, the other counting as none, and sending neither keeps them; the form always sends both. One rule rather than a 400 for sending one, and line ids are not kept across saves, since nothing refers to them yet. (agent)
- The line serializer checks an amount above 0 and a rising range itself, so a refusal names its line and saving stays at four queries however many lines there are; the database constraints stay as a backstop. (agent)
- Staff can delete an added ingredient no recipe uses, so junk can go rather than wait forever; one in use is protected. (agent)
- The admin shows `grams_per_cup` under Measures, so staff reviewing a dry good can set it. (agent)
- A catalogue file may not give `status`: the loader owns it, as it owns positions and slugs. A catalogue ingredient whose slug matches an added one takes that row over and makes it a catalogue ingredient, so recipes using it get the catalogue's flags. (agent)
- The form's draft is one flat list of lines and group headings, so moving a line past a heading moves it between groups with the same two buttons, and removing a group joins its lines to the list above, as the model's `SET_NULL` keeps lines when a group goes. (agent)
- A line's ingredient can't be changed in place: remove it and pick again. It keeps the line one picked ingredient with its own fields. (agent)
- The Unit select offers every unit Tastebook has, labelled as the page writes it. (agent)
- A line keeps its original wording through an edit, unseen, so "Show original" still shows what a source wrote. (agent)

## Out of scope

- Method steps and equipment in the form (TAS-117), and the photo (TAS-118).
- Changing an ingredient's synonyms in the admin, merging two ingredients, or adding a synonym from the form.
- Any notice to the person who added an ingredient when staff review it.
- A daily limit on adding ingredients; also any API throttling.
- A household's own ingredient list (the PRD's non-goal).
- Drag and drop, and changing a line's ingredient in place.
- Showing or editing a line's original wording in the form.
- Showing that an ingredient awaits review anywhere but "What's missing": not on the line, not in the picker.
