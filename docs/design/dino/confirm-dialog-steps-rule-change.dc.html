Proposed rule change

The boards follow the rule as it stands wherever it speaks; this says what to add where it’s silent.

Dialog, as it is

For anything that can’t be undone: says exactly what happens; the danger button names the action (“Delete account”), the other is “Cancel”, or names what it keeps when the action itself is a cancel (“Keep link”). A change that can be undone but reaches beyond the household (making a recipe public) may ask first, with a primary button that names it (“Make public”); undoing it acts at once, without asking.

Dialog, with the addition

… undoing it acts at once, without asking. A dialog that needs something first (a code from an email) asks for it in a step before the action, under the same title: that step’s button is primary and names what it does (“Send code”), and only the action itself is danger. A dialog that can only explain (a staff account can’t be deleted) has no action, and its way out is “Close”.

Why. Today a dialog has one button that acts, so “danger for what can’t be undone” covers it. A step that only sends an email isn’t the deletion: painting it danger would make the harmless press look like the final one, and leave the real one looking the same (NN/g 4, one look means one thing; NN/g 5, error prevention). Primary is still the one main action on screen while the page sits under the scrim.

“Close”, not “Cancel”, when nothing is being cancelled (Voice: a control says exactly what it does).

If it’s turned down: Send code becomes a secondary button, beside Cancel, and the dialog then has no main action until the code step.
